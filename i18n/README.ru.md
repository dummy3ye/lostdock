# LostDock

[![Python](https://img.shields.io/badge/Python-3.10+-3776AB.svg)](https://www.python.org)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](../LICENSE)
[![Platform](https://img.shields.io/badge/Platform-Windows%20%7C%20macOS%20%7C%20Linux-lightgrey.svg)](#установка)

**LostDock** — десктопный инструмент для Google доркинга и OSINT-исследований. Он сочетает
визуальный конструктор запросов с многодвижковым поиском, ограничением частоты, ротацией
прокси и постоянным хранением результатов — всё в нативном интерфейсе PySide6 (Qt),
работающем на **Windows, macOS и Linux**.

## Возможности

- **Визуальный конструктор дорков** — комбинируйте ключевые слова, точные фразы, булеву
  логику (`AND`/`OR`/`NOT`), исключения, обязательные слова, сайты, типы файлов и все
  операторы Google с предпросмотром в реальном времени.
- **Многодвижковый поиск** — Google, DuckDuckGo и Bing за единым интерфейсом, плюс режим
  Chrome «pipe», выполняющий поиск в вашем собственном браузере. Или запустите все три
  сразу и объедините результаты.
- **Ограничение частоты и антиблокировка** — token-bucket лимитер с джиттером, ротация
  User-Agent, повторные попытки с backoff и детекция CAPTCHA/ботов. Google переключается
  на рендеринг в headless Chromium, когда простой HTTP блокируется.
- **Ротация прокси** — пул прокси с ротацией round-robin, кулдауном при ошибках и
  валидацией.
- **Постоянное хранение** — каждая задача и результат в SQLite, дедупликация между
  движками.
- **Повторная проверка URL в реальном времени** — заново загружает сохранённые URL и
  аннотирует код статуса, тип контента и заголовок.
- **Планировщик дорков** — выполняет сохранённые дорки по расписанию в фоне.
- **Подсветка regex** — мгновенно подсвечивает строки, совпадающие с шаблоном.
- **Фильтры** — белый/чёрный список доменов и keep-фильтры по URL-шаблонам при экспорте.
- **Экспорт** — JSON, CSV, Markdown и стильный автономный HTML-отчёт.
- **Библиотека дорков** — сохраняйте, загружайте и управляйте дорками по имени.
- **Система плагинов** — подключайте Python-модули с хуками `setup`, `on_result` и
  `on_export`.
- **Темы** — тёмная, светлая и классические Win98 GDI.
- **Кроссплатформенность** — одна кодовая база для Windows, macOS и Linux, с установщиком/
  обновлятором для Windows.

## Установка

> Инструкции по установке намеренно предоставляются только на английском языке.

### Требования

- **Python 3.10+** — [python.org](https://www.python.org/downloads/)
- **uv** (быстрый менеджер пакетов) — [docs.astral.sh/uv](https://docs.astral.sh/uv/getting-started/installation/)

### Шаги

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/dummy3ye/lostdock.git
cd lostdock

# 2. Создайте виртуальное окружение и установите
uv venv
uv pip install -e ".[dev]"

# 3. Установите headless Chromium, используемый антиблокировочным фолбэком Google
uv run python -m playwright install chromium

# 4. Запустите
uv run lostdock
```

Если у вас нет `uv`, можно использовать обычный `pip`:

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m playwright install chromium
lostdock
```

### Альтернатива: запуск из корня репозитория без установки

```bash
cd src
QT_QPA_PLATFORM=offscreen python -m lostdock.main   # offscreen для headless-тестов
```

## Использование

1. **Соберите запрос** — введите ключевые слова, добавьте точную фразу, исключения,
   термины `AND`/`OR`, сайты (`site:`), типы файлов и inline-операторы. Скомпилированный
   запрос обновляется в реальном времени.
2. **Выберите движок** — Google, DuckDuckGo, Bing, Chrome или «all» — и количество страниц.
3. Нажмите **Run Search**. Результаты поступают в таблицу; каждый результат сохраняется в
   SQLite.
4. Используйте **Re-check URLs**, чтобы загрузить каждый результат и аннотировать его
   статус в реальном времени.
5. Задайте **Highlight** regex, чтобы подсветить интересные строки.
6. Нажмите **Export...**, чтобы сохранить в JSON, CSV, Markdown или HTML-отчёт.

## Поддерживаемые операторы

Конструктор поддерживает полный набор операторов Google:

| Оператор | Значение |
|----------|----------|
| `site:` | Ограничить результаты доменом |
| `inurl:` / `allinurl:` | Слова в URL |
| `intitle:` / `allintitle:` | Слова в заголовке |
| `intext:` / `allintext:` | Слова в тексте страницы |
| `inanchor:` | Слова в тексте якорных ссылок |
| `filetype:` / `ext:` | Ограничить типом файла |
| `cache:` | Кэшированная версия Google |
| `link:` | Страницы, ссылающиеся на URL |
| `related:` | Похожие страницы |
| `info:` | Обзор страницы |
| `define:` | Определение термина |
| `author:` | Автор результата |
| `daterange:` / `numrange:` | Числовые диапазоны |
| `loc:` | Местоположение |
| `after:` / `before:` | Фильтры по дате (`YYYY-MM-DD`) |
| `lang:` | Ограничение по языку |
| `"phrase"` | Точная фраза |
| `-term` | Исключить термин |
| `~term` | Включить синонимы |
| `*` | Подстановочный знак |
| `term1 OR term2` | Любой из терминов |

## Поисковые движки

Все движки используют единый интерфейс (`SearchEngine` в `adapters/base.py`) и по
умолчанию ограничены по частоте. Добавьте новый движок, наследуя `SearchEngine` и
регистрируя его в `adapters/__init__.py`.

- **Google** — сначала скрейпит SERP по HTTP. Если Google отвечает CAPTCHA или блокировкой
  по лимиту, страница повторно рендерится в настоящем headless Chromium (через Playwright),
  что обходит поведенческую детекцию ботов на большинстве домашних сетей. На IP дата-
  центров Google может блокировать на уровне IP в любом случае — добавьте прокси в
  Tools → Settings или используйте другой движок. Требуется однократная установка бинарника
  Chromium (`python -m playwright install chromium`). Для полностью совместимого продакшена
  интегрируйте JSON API Google Custom Search (100 бесплатных запросов в день).
- **DuckDuckGo** — лёгкий HTML-эндпоинт, обычно терпимый к автоматизированному доступу при
  умеренных скоростях.
- **Bing** — скрейпинг SERP; с ограничением частоты и возможными бот-проверками при
  масштабе.
- **Chrome (pipe)** — открывает поиск прямо в вашем собственном браузере Chrome/Chromium
  для просмотра там. Результаты не возвращаются в LostDock; это самый простой способ
  искать, когда Google блокирует всё остальное. Задайте `LOSTDOCK_CHROME`, чтобы указать
  конкретный бинарник при необходимости.
- **All** — запускает Google, DuckDuckGo и Bing для одного запроса и объединяет результаты.
  Заблокированный движок никогда не прерывает поиск; результаты дедуплицируются по URL.

## Прокси

Настройте в **Tools → Settings**. По одному на строку:

```
http://127.0.0.1:8080
socks5://127.0.0.1:1080
```

Прокси ротируются на каждый запрос; упавшие прокси уходят в кулдаун. Используйте путь
«validate» (в коде `ProxyPool.validate()`), чтобы отсеять мёртвые прокси.

## Планировщик дорков

1. Сохраните дорк (укажите имя в поле «Dork name»).
2. В **Tools → Settings** выберите дорк, задайте интервал в минутах и сохраните.
3. Фоновый планировщик выполняет подошедшие дорки, сохраняет результаты как новые задачи
   и переносит следующее выполнение.

## Повторная проверка URL

Кнопка **Re-check URLs** загружает каждый URL текущих результатов вне UI-потока, с
вежливыми задержками, аннотирует каждую строку `кодом статуса`, `типом контента` и живым
`<title>` и сохраняет результаты в базу данных. Ошибки аннотируются на месте и никогда не
роняют интерфейс.

## Плагины

Поместите файлы `*.py` в `~/.lostdock/plugins/` (или в комплектный каталог `plugins/`).
Модуль плагина может экспортировать любое подмножество:

```python
NAME = "my_plugin"

def setup(app): ...                    # один раз при запуске
def on_result(result): return result   # верните None, чтобы отбросить результат
def on_export(results, fmt, path): ... # перед экспортом
```

См. `plugins/example_skip_tracking.py` для рабочего примера.

## Хранение данных

- **База данных:** `~/.lostdock/lostdock.db` (SQLite)
- **Плагины:** `~/.lostdock/plugins/`
- Таблицы: `jobs`, `results`, `saved_dorks`, `schedules`, `settings`. Старые базы данных
  мигрируют автоматически.

## Упаковка

В проект входит `lostdock.spec` для PyInstaller. Сборка под каждую платформу:

```bash
uv pip install pyinstaller
pyinstaller lostdock.spec          # создаёт dist/lostdock
```

- **Windows:** `dist/lostdock.exe`, плюс однофайловый `lostdock-installer.exe`, который
  работает как установщик, обновлятор и деинсталлятор без прав администратора
  (`src/installer/windows/main.py`).
- **macOS:** упакуйте в `dist/lostdock.app` (подпишите через `codesign` для
  распространения).
- **Linux:** бинарник `dist/lostdock`, либо оберните в AppImage/Flatpak. `PKGBUILD` для
  Arch Linux находится в `packaging/aur/`.

## Релизы

Релизы управляются тегами и автоматизированы. Для выпуска нового релиза нужен `git-cliff`
(`cargo install git-cliff`):

```bash
make release                # поднимает версию, пересоздаёт CHANGELOG.md, коммитит и тегает
```

`make release` читает conventional commits с последнего тега, чтобы выбрать следующую
semver-версию (или передайте явную: `./scripts/release.sh 0.2.0`). Затем он поднимает
версию в `pyproject.toml` и `src/lostdock/__init__.py`, запускает набор тестов,
пересоздаёт `CHANGELOG.md` и создаёт аннотированный тег `vX.Y.Z`.

Пуш тега запускает CI, который собирает бинарники для Windows и Linux и самоподписанный
Windows-установщик, затем публикует GitHub Release с автоматически сгенерированными
заметками (сгруппированные фичи/фиксы, ссылки на issue и участников) через
[git-cliff](https://git-cliff.org).

## Отказ от ответственности

LostDock — это **инструмент для исследований в области безопасности и OSINT**. Используйте
его только против систем, которыми вы владеете или на тестирование которых у вас есть явное
разрешение. Уважайте условия использования поисковых систем: держите частоту низкой,
ответственно используйте прокси и никогда не применяйте этот инструмент для
